# Primer29 RMK ファームウェア (ProMicro RP2040)

遊舎工房 Primer29 のプロセッサボードを ProMicro RP2040 に換装した個体向けの、
[RMK](https://github.com/HaoboGu/rmk) 0.8.2 ベースのファームウェアです。
Vial 対応(レイアウト内蔵)、duplex matrix は RMK の `BidirectionalMatrix` を使用しています。

## 以前動かなかった原因(修正済み)

WSL 上で試作したバージョンで「キー位置がバラバラ」「最下行が無反応」だった原因は2つ:

1. **行ピンが1本ずれていた**: Row は GP4-8 ではなく **GP5,6,7,8,9**(QMK 版 config.h と同じ)。
   GP9 が pins 配列に無かったため最下行(R4)が全滅し、他の行は1行ずれて認識されていた。
2. **スキャン駆動方向が逆だった**: QMK は active-low(駆動側を Low)、RMK の
   `BidirectionalMatrix` は active-high(駆動側を High)。ダイオードの導通方向に対して
   out/in の役割が QMK と逆転するため、`scan_map` の全 `Pins(a, b)` を `Pins(b, a)` に反転した。
   これが「隣接列ペアの入れ替わり」として観測されていた。

テスト配列(A,B,C…)とテンキー配列の両方の実測結果・全29キー(無反応マス含む)が
この修正内容で完全に一致することを確認済み。

3. **ストレージ**: RMK はキーマップをフラッシュに保存するため、ファーム書き換えだけでは
   キーマップが更新されない。`main.rs` の `CLEAR_STORAGE`(現在 `true`)で対処。

## ビルド (GitHub Actions)

`rmk/` 配下を変更して push すると、`.github/workflows/build-rmk.yml` が自動でビルドし、
Actions の Artifacts に **primer29-rmk-uf2**(`primer29.uf2`)が生成されます。
手動実行は Actions タブ → "Build RMK firmware (Primer29)" → Run workflow。

ローカル(要 Rust + cargo-make)では:

```bash
cd rmk
cargo make uf2   # → primer29.uf2
```

## 書き込み

1. BOOTSEL を押しながら USB 接続(または BOOTSEL+リセット同時押し)
2. `RPI-RP2` ドライブに `primer29.uf2` をコピー

## 書き込み後の手順(重要)

1. まず `CLEAR_STORAGE = true` のビルドを書き込み、全キーの配置が正しいか確認する
2. 正しければ `src/main.rs` の `CLEAR_STORAGE` を `false` に変えて再ビルド・再書き込み
   (これをしないと Vial での変更が起動のたびに消える)

## Vial

- https://vial.rocks/ (Chrome/Edge) またはデスクトップアプリで自動認識
- セキュリティアンロック: **Ins(左上)+ /(右上)を同時長押し**
- レイヤーは4枚(レイヤー0のみ割り当て済み、1-3は透過)

## キーマップ(レイヤー0)

| row\col | 0     | 1    | 2    | 3       | 4 | 5 | 6        |
|---------|-------|------|------|---------|---|---|----------|
| 0       | Ins   | Home | PgUp | NumLock | - | * | /        |
| 1       | Del   | End  | PgDn | 7       | 8 | 9 | (無)     |
| 2       | (無)  | (無) | (無) | 4       | 5 | 6 | +(2u)    |
| 3       | Shift | ↑    | Ctrl | 1       | 2 | 3 | (無)     |
| 4       | ←     | ↓    | →    | (無)    | 0 | . | Enter(2u)|

※ 最上段の記号の並びはヒアリング通り `- * /` にしてあるが、オリジナル QMK 版の
デフォルトは `/ * -` の順。実物のキーキャップと違っていたら Vial で入れ替えるか
`keymap.rs` の row0 を修正すること。

## シーケンスマクロ

「**キー1をタップ → 素早くキー2をタップ**」または「**キー1を押したままキー2を押す
(重ね押し/ロール打ち)**」で、別のキー(または Vial のダイナミックマクロ)が入力される
機能。実装は `src/sequences.rs`。`main.rs` はこの状態機械を通してから matrix のイベントを
配送する(`run_devices!` マクロは経由しない)。

トリガー(キー1/キー2)も出力も **すべて Vial 上で設定できる**。論理マトリクスは
8行×7列で、行0-4 が物理キー、行5-7 は物理キーの無い「設定用の仮想行」:

| 仮想行 | 意味 |
|--------|------|
| 行5 (TRIG1) | 列 n = シーケンス n の「キー1」のキーコード |
| 行6 (TRIG2) | 列 n = シーケンス n の「キー2」のキーコード |
| 行7 (OUT)   | 列 n = シーケンス n の出力(キーコードや Vial マクロ) |

Vial では本体29キーの下に3行×7列として表示される(**縦1列 = 1シーケンス**。上から
キー1・キー2・出力)。シーケンスは最大7個(列0-6)。

### 動作仕様

1. **Idle**: 押されたキーのキーコードがいずれかの有効なシーケンスのキー1に一致したら、
   press を転送せず保留する。
2. **キー1押下中**: 次の3つのどれかで確定する。
   - `SEQ_OVERLAP_MS` 以内に **キー2の press** → 発動(重ね押しパス)。キー1・キー2の
     本来の入力は届かず、出力(OUT)の合成 press が送られる。
   - `TAP_TERM_MS` 以内に **キー1の release** → タップ成立、キー2待ちへ。
     (`TAP_TERM_MS` 超~`SEQ_OVERLAP_MS` 内の release はタップ不成立で、押した通りに転送)
   - `SEQ_OVERLAP_MS` 経過(押しっぱなし)→ ホールド操作として確定し、保留していた
     press をそのまま転送する(タイマーで即時確定するので入力遅延はほぼ無い)。
   途中で無関係のキーが来た場合も保留分を転送して通常入力に戻る。
3. **キー2待ち(タップパス)**: `SEQ_GAP_MS` 以内にキー2の press が来れば発動。
   キー1を連打した場合はタップし直しとして扱う。タイムアウトや無関係イベントの場合は
   保留していたタップ(press+release)をそのまま転送する。
4. **発動中**: キー2を離すと出力の合成 release が送られる。**キー2を押し続ける限り
   出力キーはホールド(リピート)される**。重ね押しパスではキー1の release は
   どのタイミングで来ても静かに破棄される(キー1→キー2、キー2→キー1 どちらの順で
   離しても良い)。

### 既定の3シーケンス(レイヤー0 の初期値)

| 列 | キー1 (TRIG1) | キー2 (TRIG2) | 出力 (OUT) |
|----|---------------|---------------|------------|
| 0  | Home          | PgUp          | (未設定)   |
| 1  | Del           | End           | (未設定)   |
| 2  | ↑             | ↓             | (未設定)   |

出力が未設定(`KC_NO`)のままだと、発動しても何も入力されない。まず Vial で
OUT 行(いちばん下の行)に出したいキーを割り当てること。

### Vial での設定方法

- **出力を変える**: OUT 行(下段)の該当列に好きなキーコード、または Vial の
  ダイナミックキーマクロ(M0 等)を割り当てる。
- **トリガーを変える**: TRIG1 行(上段)/ TRIG2 行(中段)の該当列に、トリガーに
  したいキーのキーコードを割り当てる。物理キーの判定は「キーコード一致」で行うので、
  物理キー側を Vial で並べ替えてもトリガーは追従する。
- **シーケンスを追加する**: 空いている列(3-6)の TRIG1 と TRIG2 の両方にキーコードを
  設定すれば、その列が有効になる(ソース編集・再ビルド不要)。
- **シーケンスを無効化する**: その列の TRIG1(または TRIG2)を `KC_NO` にする。
- すべてライブ反映(設定した瞬間から効く)。Vial の編集はフラッシュに保存されるので
  再起動後も維持される。

### レイヤーについての注意

- トリガー判定(TRIG1/TRIG2 と物理キーの照合)は **レイヤー0 の値だけ**で行われる。
  レイヤー1-3 に切り替えて打鍵した場合も、判定にはレイヤー0 のキーコードが使われる
  (rmk 0.8.2 にレイヤー状態をクレート外から読む API が無いための制限)。
  トリガーの設定・変更は必ずレイヤー0 で行うこと。
- OUT 行の解決は RMK 本体が行うため、通常のレイヤー透過が効く(レイヤー1-3 の行5-7 は
  既定で Transparent)。出力の設定もレイヤー0 で行えば全レイヤーから同じ出力になる。
- 同じキーコードを複数列の TRIG1 に設定した場合は、いちばん左の列が使われる。

### タイミング定数

- `TAP_TERM_MS = 200` — キー1のタップ判定時間
- `SEQ_GAP_MS = 300` — キー1リリースからキー2プレスまでの猶予(タップパス)
- `SEQ_OVERLAP_MS = 300` — キー1押下からキー2プレスまでの猶予(重ね押しパス)

いずれも `src/sequences.rs` 冒頭の `const`。

### 旧バージョンからの更新時の注意

シーケンスマクロ導入で論理マトリクスが 5×7 から 8×7 に変わった。フラッシュに保存された
旧レイアウト時代の Vial 設定と食い違いが出た場合は、「書き込み後の手順」の要領で
`CLEAR_STORAGE = true` のビルドを一度書き込んでストレージをクリアしてから
`false` に戻すと確実。
